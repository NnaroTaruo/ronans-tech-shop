# Store layout and customer screens

Stage 1 established the shared header/footer, typography, colors and setup page. Stage 2 extends that established system to home/catalog/details/cart; admin surfaces remain later stages. The user's simple professional light-store brief and required product cards control the scope. The existing palette and component style are preserved.

- Ground: `#f4f6f7`; full text: `#192e35`; restrained action accent: `#116050`; secondary surface: `#e3efeb`; white header/content panels.
- One installed readable face, Segoe UI with sans-serif fallback. Font files/network loading are unnecessary for this local foundation. Body starts at 16px; headings use a clear size change.
- Shared max width 72rem; symmetric 20px mobile and 32px larger-screen gutters. Header wraps on phones. All implemented navigation links reach real page sections.
- Flat square action button; no card shadows or gradients. Visible 3px keyboard-focus outline, skip link, semantic header/nav/main/footer, reduced-motion scrolling fallback.
- Subject-specific identity is the keyboard mark and Ronan's shop name. The setup page honestly reports database readiness and seed counts rather than showing unimplemented shopping actions.
- Product image references use bundled, source-documented geometric category illustrations. They now render on customer screens; they are deliberately shared category images rather than product-specific photography.

Stage 2: the home pairs its store introduction with the keyboard illustration, then a flat demo banner, category links and featured products. The listing uses a four-column desktop product grid, two columns on tablets and one on phones; the filter form collapses to one column on mobile. Product details pair media and a quantity form. The cart uses rows plus a summary on desktop and stacked blocks on mobile. Forms have readable labels and 48px controls; actions stay aligned within product rows. Validation uses `#9a2929` text as well as words. Current-data and persistence behavior is explained in README; product pages avoid setup instructions.

Product-list inspection evidence is recorded at 375px/1280px. The retained title-size and first-screen-card-count warnings are explained in the test log. Other customer layouts, keyboard interaction and populated-cart controls still need manual browser review; no blanket responsiveness pass is claimed.

Stage 3 extends the same flat light layout to checkout and confirmation. Checkout pairs labelled delivery/payment fields with a compact current-order summary; on phones these stack. Field errors use text plus `aria-invalid`, and shared status/review controls expose change/failure states. Confirmation groups order/customer details and saved item snapshots, wraps long values, and displays Philippine time. The shorter desktop summary intentionally stays content-sized beside the taller form. Empty checkout has zero totals and a disabled save action.

Checkout and fictional saved-confirmation layouts were inspected at 375px/1280px. Retained heading-size and unequal-content-height warnings are documented. Complete purchase, field-error/re-review interaction, keyboard behavior and browser cleanup remain manual checks. Evidence and limits belong in `docs/test-log.md`; full customer/admin compliance is not implied.

Stage 4 extends this established world in Operate mode. Mobile folds the menu and filters into native details controls. Login is a centered, capped form; admin titles are 24px, figures 26px, controls 48px and flat. Recent orders/low-stock and customer/payment panels remain content-sized to avoid padded empty panels. No chart is needed for the six required all-time figures. Scope, screenshot review and retained warnings are recorded in the test log; keyboard/form interaction is not inferred from snapshots.
